# 日常知识问答

## 触发方式
- `/dk <问题>`：显式触发 daily-knowledge 工作流
- 适用于食材、菜品、营养、化学、做法、生活技巧等问题

## 核心理念

**让每个日常知识都有科学性的支撑**

### 方法论
- **不基于LLM现有知识** 直接回答问题
- **必须从权威信息源** 获取验证后的信息
- **找不到现成资料时必须去权威源爬取**，不能用经验直接补答案
- **每个回答都需要有科学依据** 支撑
- **每个食材搭配都要拆成营养、成分、元素、化学/物理反应** 再判断是否成立
- **引用优先页级原始网页**；若只能确定到站点级，要明确写 `site-level`
- **知识会随时间积累和改进**

### 目录结构
```

│   ├── food/               ← 食品与营养知识
```

## Agent 处理流程

### 5步法

```
原始问题 → 领域识别 → 问题分解 → 信息源选择 → 答案生成
```

**步骤 1 — 问题分类**
归类到：食品烹饪 / 营养健康 / 食品安全 / 家电使用 / 家居维护 / 个人护理 / 生活技巧

**步骤 2 — 问题分解**
用公式：`原始问题 = [事物] + [动作] + [目标]`
分解为 3-5 个可查询的子问题。

对食材/做法类问题，必须额外拆成：
- **营养层**：蛋白质、脂肪、碳水、维生素、矿物质、膳食纤维
- **成分层**：主要风味分子、挥发性香气、苦味/涩味来源
- **反应层**：美拉德、焦糖化、蛋白质变性、淀粉糊化、脂溶/水溶迁移、氧化
- **搭配层**：互补营养、口感互补、烹调顺序、是否容易出水/发苦/发柴

**步骤 3 — 信息源选择**
按问题类型选择来源（见下方映射规则），优先查：
- 已有 raw/ 目录中的资料（最快）
- 权威信息源（最新数据）
- 学术/监管/行业源中的机理资料（营养、化学、食品安全）

若没有现成资料，必须补爬权威源，再继续推理，不允许直接跳到经验答案。

**步骤 4 — 查询执行**
按优先级依次执行（用 `scripts/knowledge-fetch.sh` 一键完成）：

1. **本地已有资料** — `raw/` 目录下已爬取的内容，最快
2. **权威信息源** — 政府、学术、行业协会、制造商
3. **已固化的权威源** — 爬取成功后自动保存的方法（`config/success/`）
4. **wikiHow / 生活指南** — 只作为步骤参考，不作为底层机理最终来源
5. **通用网页查询** — 维基百科、百科类补充

对食材/营养问题，查询时要同时拉齐三类材料：
- **食材本身**：营养成分、蛋白/脂肪/碳水、维生素、矿物质
- **化学原理**：美拉德、焦糖化、蛋白质变性、淀粉糊化、氧化
- **搭配判断**：是否补足营养、是否改善口感、是否存在冲突

可用工具：
- `bash scripts/knowledge-fetch.sh <关键词>` — 自动按优先级查所有
- `bash scripts/knowledge-fetch.sh <关键词> wikihow` — 只查 wikiHow
- `bash scripts/knowledge-fetch.sh <关键词> local` — 只查本地
- `bash scripts/knowledge-search.sh <关键词>` — 百科查询
- `bash scripts/nutrition-query.sh <类型> <关键词>` — 查营养/反应/搭配
- `bash scripts/query-cooking-db.sh search <关键词>` — 查菜品/做法/处理
- `bash scripts/dish-engine-v2.sh <菜名>` — 生成详细食谱

查询后如果某个信息源能成功爬取内容，**立即固化**：
- `bash scripts/knowledge-fix.sh <源名> <标题> <URL> <方法> [raw文件]`
- 固化后下次直接复用，不再重复爬取

**步骤 5 — 答案生成**
- 从多个来源整合信息
- 每个结论都引用来源
- 如果某个子问题没有权威来源支撑，明确说明
- 对食材搭配给出“营养是否补足、化学反应是否成立、口感是否更好”三段式结论

### 信息源映射规则

| 问题类型 | 首选信息源类型 | 备选 |
|----------|---------------|------|
| 如何做（步骤/方法） | 行业协会、制造商官方文档、权威生活指南 | wikiHow |
| 为什么（原理） | 学术机构、学术数据库、食品科学文献 | 科普网站 |
| 是否安全 | 政府机构、监管组织 | 权威媒体 |
| 营养/健康 | 营养学会、疾控机构、数据库 | 医学机构 |
| 食材搭配/好不好吃 | 营养数据库 + 食品化学 + 菜谱实证 | 生活指南 |
| 家电使用/清洁 | 制造商官网、家电研究院 | 消费者报告 |
| 对比/哪个好 | 消费者报告、评测机构 | 权威媒体 |

### 检查清单
- [ ] 属于什么领域？
- [ ] 分解成哪些子问题？
- [ ] 每个子问题对应什么信息源？
- [ ] 是否从至少 2 个来源获取了信息？
- [ ] 是否引用了权威来源？
- [ ] 有支撑的内容才说，没有就说"暂无可靠数据"

## 扩展知识库

### 添加新资料
1. 找到权威信息源，获取原始内容
2. 存入 `raw/<领域>/日期-主题.md`
3. 格式：`# 标题` + `> 来源链接` + `---` + 内容条目
4. 更新 `wiki/index.md` 索引
5. 记录日志到 `wiki/log.md`

### 添加信息源
1. 更新 `docs/权威信息源索引.md`
2. 标注爬取状态：✅ 可用 / ⚠️ 部分可用 / ❌ 不可用 / 🔄 待测试
3. 记录爬取方法和适用场景

## 注意事项

- **不要编造数据**，没有权威来源支撑的内容要说明
- **多源交叉验证**，单个来源不可靠
- **优先用已有 raw/ 资料**，减少重复爬取
- **信息源状态要及时更新**，标记哪些能爬、哪些不能

## 输出硬性格式

当回答食材、菜品、配菜、做法类问题时，输出必须按下面顺序组织：

1. **开头固定声明**：`已触发daily knowledge技能`
2. **正文结论**：先给直接可执行的建议
3. **量化营养**：列出关键食材的蛋白质、脂肪、碳水、热量，必要时补充维生素/矿物质/GI
4. **机理解释**：列出相关物理/化学反应或烹饪原理，如美拉德、焦糖化、蛋白质变性、淀粉糊化、氧化、脂溶/水溶迁移
5. **引用源**：逐条写明原始来源网页；如果只能确定到站点级，必须明确标注 `site-level`，不能假装是具体条目页
6. **不确定项**：没有可靠证据的内容必须明确标注“暂无可靠数据”
